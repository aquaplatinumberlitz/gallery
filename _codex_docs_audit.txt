Audit the `/docs/` directory of gallery-repo for contradictions, stale/outdated content, logic errors, and inaccurate references.

**Context:** 
- The project just completed a major 11-phase refactor: Catalog Scan Pipeline and Unified Status.
- Old endpoints `/api/scan`, `/api/index/status`, `/api/index/rebuild`, `/api/libraries/{id}/repair` have been removed.
- Old configs `GALLERY_DB_REQUIRED`, `ENABLE_WARM_INDEXED_LISTING`, `ENABLE_SCHEDULED_REFRESH`, `SCHEDULED_REFRESH_*`, `WATCHER_ROOTS`, `WATCHER_DEBOUNCE_SECONDS` have been removed.
- New endpoints: `/api/browse`, `/api/libraries/{id}/status`, `/api/libraries/status`, `/api/libraries/{id}/rebuild`.
- New configs: `GALLERY_CATALOG_*` family, `GALLERY_METADATA_EVENT_THROTTLE_MS`.
- `GALLERY_DB_REQUIRED` and related conditional DB-required logic removed.
- The plan files have been archived to `docs/archived/`.
- Phase 10 already updated `docs/ARCHITECTURE.md`, `docs/CONFIGURATION.md`, and `frontend/src/db/README.md`.

**Scope:** All `.md` files under `docs/` (including subdirectories like `docs/archived/`, `docs/research/`, `docs/plans/`, etc.)

**Check for:**

1. **Outdated endpoint references** — any file still mentioning `/api/scan`, `/api/index/status`, `/api/index/rebuild`, `/api/libraries/{id}/repair` as current endpoints.
2. **Outdated config references** — any file still mentioning `GALLERY_DB_REQUIRED`, `ENABLE_WARM_INDEXED_LISTING`, `ENABLE_SCHEDULED_REFRESH`, `SCHEDULED_REFRESH_*`, `WATCHER_ROOTS`, `WATCHER_DEBOUNCE_SECONDS`, `root_path`.
3. **Logic contradictions** — files that describe behavior the current code doesn't implement (e.g., describing DB-required fallback behavior, the old scan endpoint, the repair endpoint, GALLERY_DB_REQUIRED conditional paths).
4. **Stale ARCHITECTURE.md sections** — any module/route/flow descriptions that don't match the current codebase after Phase 1-11.
5. **Stale CONFIGURATION.md sections** — any config descriptions that reference removed configs or missing new configs.
6. **Cross-reference accuracy** — links between docs files that are broken (e.g., pointing to files in `docs/plans/` that were moved to `docs/archived/`).

**DO NOT** modify any files. Just find issues and report them in a structured table format:

| File | Issue type | Location (line ~) | Description | Severity (P0/P1/P2/P3) |
|------|-----------|-------------------|-------------|------------------------|

Severity guide:
- P0 = Will cause confusion or breakage (wrong endpoint/config described as current)
- P1 = Stale but not dangerous (references removed feature as historical context without clarifying it's removed)
- P2 = Minor inaccuracy (slightly outdated description, missing new features)
- P3 = Cosmetic (typo, broken link)

After auditing, summarize the findings. Do NOT make any changes.
